# 애드센스 "가치가 별로 없는 콘텐츠" 반려 대응

애드센스가 `soo-c9.blogspot.com` 을 **"가치가 별로 없는 콘텐츠"**로 반려한 건에
대한 원인 분석과 수정 내역입니다.

---

## 먼저: 코드로 해결되지 않는 부분

정직하게 짚고 갑니다.

1. **이 저장소의 수정만으로는 승인되지 않습니다.** 이미 발행된 24편은 코드를
   고쳐도 그대로 남아 있습니다. 아래 "사람이 해야 하는 일"을 하셔야 합니다.
2. **어떤 코드도 애드센스 승인을 보장하지 못합니다.** 자동 검사는 "확실히
   걸릴 것"을 걸러낼 뿐이고, 최종 판단은 사람 심사자와 Google의 시스템이
   합니다.
3. **가장 큰 위험은 코드 구조가 아니라 운영 방식에 있습니다.** 사람 검토 없이
   LLM으로 생성한 글을 매일 자동 발행하는 것은, Google이 정책 문서에서
   *scaled content abuse*(대규모 콘텐츠 남용)로 설명하는 패턴에 그대로
   해당합니다. AI를 썼다는 것 자체가 아니라 **"검색 순위를 위해 사람 가치를
   더하지 않고 양산하는 것"**이 문제입니다. 이 저장소의 수정은 그 신호를
   줄이지만 없애지는 못합니다. 결국 사람이 읽고 손보는 단계가 필요합니다.

---

## 무엇이 문제였는가

이전 `generate_post.py` 의 `_render_html()` 은 24편 전부에 대해 예외 없이
아래 한 가지 HTML을 만들어냈습니다.

```html
<p>서론</p>
<h2>소제목</h2><p>본문</p><ul>…</ul>   ← 4~6회 반복
<h2>마무리</h2><p>결론</p>              ← 매번 똑같은 리터럴
```

여기서 나오는 문제는 추측이 아니라 코드에서 확정됩니다.

| # | 문제 | 왜 걸리는가 |
|---|---|---|
| 1 | 이미지도 표도 없음 | `<img>`/`<table>` 을 넣는 경로가 아예 없었음. 전편이 벽글 |
| 2 | 내부 링크 0개 | 24편이 서로 오가는 링크가 없어 각 글이 고립된 페이지 |
| 3 | 24편의 구조가 완전히 동일 | 마지막 `<h2>` 가 전부 `마무리`. 템플릿 판정의 직접 근거 |
| 4 | 소개·문의·개인정보처리방침·면책조항 페이지 없음 | 사이트 신뢰성 확인 항목이 통째로 비어 있었음 |
| 5 | `meta_description` 이 생성만 되고 버려짐 | 발행 body에 넣는 코드가 없었음 |
| 6 | 분량 기준(1,200자)이 후하게 계산됨 | 소제목·리스트 글자까지 합산해서 셈 |
| 7 | HTML 이스케이프 없음 | 본문에 `<` 나 `&` 가 하나만 들어가도 뒤쪽 마크업이 깨짐 |
| 8 | YMYL 주제를 하루 2편 | 실손보험·소득공제·고혈압 등은 가장 엄격한 기준이 적용됨 |

## 코드에서 고친 것

| 항목 | 이전 | 지금 |
|---|---|---|
| 결론 소제목 | 고정 리터럴 `마무리` | LLM이 주제에 맞게 작성 |
| 요약 표 | 없음 | 글머리에 `핵심 요약` 표 |
| 내부 링크 | 없음 | 같은 카테고리 최근 글 3개 자동 링크 |
| HTML 이스케이프 | 없음 | 전체 이스케이프 |
| 분량 기준 | 1,200자(후한 계산) | 산문 1,600자 + 렌더 결과 1,700자 |
| 발행 전 검사 | 분량만 | `quality.py` 게이트 전체 (미달이면 발행 중단) |
| 필수 페이지 | 없음 | `publish_pages.py` + 템플릿 4종 |
| 발행 후 점검 | 없음 | `audit_blog.py` + 주간 워크플로 |
| 발행 빈도 | 하루 2편 | 하루 1편 |

핵심은 **`quality.py` 하나를 발행과 감사가 같이 쓴다**는 점입니다. 발행은
됐는데 감사에서 떨어지는 글이 생길 수 없습니다.

---

## 사람이 해야 하는 일 (순서대로)

### 1단계 — 시크릿 2개 추가

저장소 → Settings → Secrets and variables → Actions

| Secret | 값 |
|---|---|
| `BLOGGER_CONTACT_EMAIL` | 실제로 연락 가능한 이메일 주소 |
| `BLOGGER_BLOG_NAME` | (선택) 블로그 이름. 비우면 Blogger 설정값을 씀 |

> 이 저장소는 **public** 입니다. 이메일을 파일에 직접 적지 마세요. 그래서
> 페이지 템플릿은 `{{CONTACT_EMAIL}}` 토큰만 갖고 있고, 값은 발행 시점에
> 시크릿에서 주입됩니다.

### 2단계 — 필수 페이지 게시

Actions → **Blogger Required Pages** → Run workflow

그다음 **반드시** Blogger 관리 화면에서:

> 레이아웃 → 가젯 추가 → **페이지** → 소개·문의·개인정보처리방침·면책조항
> 네 개를 모두 표시

페이지를 만들어도 메뉴에 걸지 않으면 심사자가 찾지 못합니다. **이 단계를
건너뛰면 1~2단계가 무의미합니다.**

`blogger_blog/pages/about.html` 은 일반적인 내용으로 채워져 있습니다. **본인
이야기로 고쳐 주세요.** 누가 왜 쓰는 블로그인지가 심사에서 실제로 봅니다.

### 3단계 — 지금 상태 진단

Actions → **Blogger AdSense Audit** → Run workflow

실행 요약(Summary)에 어느 글이 왜 미달인지 전부 나옵니다. 이게 재심사 요청
전에 봐야 할 목록입니다.

### 4단계 — 기존 24편 처리 ⚠️ 가장 오래 걸리는 단계

감사 리포트의 미달 글을 하나씩 처리합니다. **자동화할 수 없습니다.**

각 글에 대해 셋 중 하나를 고르세요.

- **보강** — 본문을 1,700자 이상으로 늘리고, 소제목을 다듬고, 관련 글 링크를
  추가합니다. 이때 **사실 확인을 반드시 하세요.** LLM이 지어낸 수치나 제도
  설명이 섞여 있을 수 있고, 금융·건강 주제에서 그건 승인 문제 이전에 독자에게
  해를 끼칩니다.
- **통합** — 비슷한 주제 2~3편을 하나의 충실한 글로 합치고 나머지는 내립니다.
  글 수가 줄어도 평균 품질이 오르는 쪽이 낫습니다.
- **비공개** — Blogger에서 초안으로 되돌립니다. 살릴 가치가 없는 글은 지우는
  게 가장 빠른 개선입니다.

> 24편을 전부 보강하기 어렵다면, **가장 좋은 10~15편만 남기고 나머지를 내리는
> 편이 낫습니다.** 얇은 글 24편보다 충실한 글 12편이 심사에 유리합니다.

### 5단계 — 이미지 넣기

자동 검사는 표가 있으면 넘어가지만, **직접 만든 이미지가 있는 글이 확실히
낫습니다.** Blogger API v3에는 이미지 업로드 기능이 없어서 이 부분은
자동화하지 않았습니다. Blogger 편집기에서 직접 넣으세요. 스크린샷, 직접 만든
도표, 직접 찍은 사진이 좋습니다. **다른 곳에서 가져온 이미지는 저작권 문제로
오히려 위험합니다.**

### 6단계 — 재심사 요청

**Blogger AdSense Audit 워크플로가 초록불이 된 뒤에** 요청하세요.
빨간불 상태로 요청하면 반려되고, 반복 반려는 불리하게 작용합니다.

## 이후 운영

- 매일 09:00 KST에 1편이 자동 발행됩니다. 게이트를 통과하지 못하면 **발행하지
  않고 그날을 건너뜁니다.** 워크플로 실패는 정상 동작입니다.
- 매주 월요일 감사가 돕니다. 빨간불이면 그 주에 손볼 글이 있다는 뜻입니다.
- **자동 발행된 글도 주기적으로 읽어 보세요.** 이 파이프라인은 얇은 글과
  템플릿을 막을 뿐, 내용이 맞는지는 판단하지 못합니다.

## 임계값을 조정하려면

전부 `blogger_blog/scripts/quality.py` 상단에 모여 있습니다.

```python
MIN_TEXT_CHARS = 1700              # 본문 최소 글자 수
MIN_HEADINGS = 3                   # 소제목 최소 개수
MAX_SHARED_SENTENCE_RATIO = 0.30   # 다른 글과 겹치는 문장 허용 비율
NEAR_DUPLICATE_JACCARD = 0.60      # 중복 글 판정 유사도
MIN_PUBLISHED_POSTS = 20           # 사이트 최소 글 수
MIN_PASS_RATIO = 0.90              # 통과해야 하는 글의 비율
```

**이 숫자들은 Google이 공개한 기준이 아닙니다.** 정책 문서가 서술적으로
요구하는 것을 자동 검사로 옮긴 운영용 값입니다. 낮추면 게이트가 느슨해지고,
그건 반려 상태로 되돌아가는 길입니다.
